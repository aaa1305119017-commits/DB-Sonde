# AI 分析流程

AI 分析通过指标目录和只读查询工具获取数据，再生成分析结论与看板。
运行前需配置可用的模型服务、数据库连接及指标定义。

## 工作流

流程定义位于 `src/features/agent/analysisGraph.ts`，支持自然语言提问和明确指定指标、日期、维度的参数模式。

1. **规划**：确定问题、指标、日期范围、维度和筛选条件。
2. **取数**：按指标定义生成并执行查询计划。
3. **检查数据**：检查查询结果，阻止未通过验证的数据进入后续分析。
4. **探索证据**：提问模式按需要补充查询，并记录证据缺口。
5. **分析与复核**：生成结论，检查结论与查询证据是否一致。
6. **设计看板**：需要看板时，生成组件及数据绑定，检查定义并渲染预览。
7. **保存**：完成设计检查后保存看板，返回保存结果。

重试次数和运行步数有上限。查询失败、指标缺失或检查未通过时显示具体原因。
结论复核失败后保留分析草稿及问题说明，不继续生成看板。
图像评审受模型能力及配置影响；详情见 `designLoop.ts`。

## 指标与证据

- 指标使用稳定 ID，计算口径、维度和汇总方式由指标中心定义。
- 日期计算、事实统计和比率汇总由代码处理，模型负责问题理解和分析表达。
- 分析结论通过证据标识引用查询结果。
- 看板绑定指标或已验证的查询计划，保存前检查绑定与显示单位。
- 新增组件字段时，需同步界面、设计契约、校验器和导出逻辑。

## 会话边界

`analysisSession.ts` 为每次运行创建指标目录快照、查询计划和结果缓存。
生成与保存看板前检查指标目录是否变化；定义变化时要求重新分析。

取消或释放会话后停止后续派发，丢弃失效回调并清理未完成的设计草稿。
这不保证数据库服务端已终止当前 SQL，驱动取消能力需单独处理。

## 模型与数据

模型配置支持云端接口、本地兼容接口和内置运行时，按配置为不同节点选择模型。
未配置或不可用的服务应报告错误，不使用占位结果代替实际分析。

使用云端模型时，问题、相关元数据和分析所需的结果信息会按功能及配置发送到模型服务。
样本行默认关闭，可通过 AI 设置调整；关闭样本行不等同于关闭所有分析数据传输。
应根据所用模型服务和数据要求配置分析范围。

## 实现入口

| 文件或目录 | 职责 |
| --- | --- |
| `analysisWorkflow.ts` | 提问与参数模式入口 |
| `analysisGraph.ts`、`graph.ts` | 节点、条件分支和执行控制 |
| `analysisSession.ts` | 会话装配与查询资源生命周期 |
| `state.ts` | 工作流状态和证据结构 |
| `nodes/` | 取数、分析、设计和复核节点 |
| `tools/` | 数据与看板工具契约 |
| `model/` | 模型选择、结构化请求和重试 |
| `designLoop.ts` | 预览、图像评审和保存 |
| `audit.ts` | 节点、工具调用与耗时记录 |

以上路径相对于 `src/features/agent/`。

## 验证

```sh
npm run test:analysis
npm run test:nodes
npm run test:session
npm run test:design
npm run test:cloud-privacy
```

完整检查使用 `npm run check`。自动化回归不能代替实际数据和模型上的分析质量评估。
