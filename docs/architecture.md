# DB Studio 模块边界与扩展规范

DB Studio 是可独立使用的数据库客户端。ETL、调度、指标、AI 和核对服务是可选能力。一个集成未配置或不可用，不应阻止数据库连接、查询、编辑和工作区恢复。

## 依赖方向

- `App.tsx` 是界面与可选功能启动的装配入口。
- `store/appStore.ts` 只组装连接、对象树、查询、工作区、界面五个 slice，并保留旧的类型导出供兼容。
- `store/appTypes.ts` 定义工作区契约；`treeModel.ts` 管对象树构造；`stateKeys.ts` 管身份编码；持久化分别放在 `workspacePersistence.ts` 和 `treePreferences.ts`。
- slice 不导入可选功能和界面。会话密码只在连接 slice 内部持有。
- `features/*` 拥有各自的界面、状态和业务流程。纯模型接受数据参数，禁止读取全局 store 或直接发起平台调用。
- `lib/api.ts` 是桌面命令门面；Rust 保留数据库连接、事务、凭据和文件访问的最终执行边界。前端能力声明不能代替后端验证。

这仍然是模块化单体，共享工作区状态、平台 API 和数据库驱动库是有意保留的公共依赖。没有引入进程间调用、插件加载器或微服务来代替模块设计。

## 外部系统适配

### ETL

入口 `features/etl/adapters/index.ts` 注册解析器。适配器将外部格式转为 `EtlJob` / `Endpoint`；核心血缘只消费这些内部模型。外部系统无需使用特定目录、文件名或表结构。

通用导入支持作业数组或 `{ "jobs": [...] }`；如外部字段不同，在客户端输入 JSON Pointer 映射。例如现有文件：

```json
{"tasks":[{"code":"stock-sync","title":"库存同步","inputs":[{"schema":"erp","relation":"stock"}],"outputs":[{"schema":"mart","relation":"inventory"}]}]}
```

客户端映射：

```json
{"jobs":"/tasks","id":"/code","name":"/title","sources":"/inputs","targets":"/outputs","endpoint":{"database":"/schema","table":"/relation"}}
```

映射随接入源保存，后续补充导入复用。映射只读取数据，不执行表达式或外部脚本。未认识的字段不进入标准作业对象。作业标识重复、路径无效、缺少端点会报错；不能猜测血缘。

文件扫描与通用 JSON 导入是两个入口。DataX 解析和文件扫描的运行环境要求只属于对应适配器；通用 JSON 导入不要求 Python、SSH、ETL 目录或调度服务。`parseFileInventory` 接收 SQL 解析函数；单段解析失败记录覆盖缺口，仍保留文件身份和后续可解析的数据流。

新增外部格式：实现适配器，添加正常输入、歧义输入和错误输入测试，再注册。不在 `lineageStore` 中增加外部产品 JSON 字段判断。

### 指标目录

目录格式继续为 `version: 1`，建议每个目录提供独立 `id` 和 `name`。指标保留稳定 `id`，可以附带 `catalogId` / `catalogName`。

连接绑定仅修改当前目录。目录内也允许各指标分别绑定；此时显示“多个连接”。跨目录重复指标 ID 拒绝覆盖，避免已保存看板引用悄悄改变含义。

无目录元数据的旧记录放入兼容分组，旧指标 ID 不重编号。重新导入有明确目录 ID 的定义时可用“覆盖”认领旧记录。没有 ID 的历史目录不会被程序猜测拆分。任意数据库连接均可选择，SQL 表达式或模板仍需符合该连接方言，程序不会把 MySQL 专用 SQL 伪装成跨数据库 SQL。

### 核对服务

服务独立配置 URL，不再从 ETL 主机推测。服务端可直接配置 `rules`，不需要 `etlRoot`；`refreshCatalogBeforeRun` 与 DataX 自动规则属于可选的现有适配入口。

通用核对规则例子：

```json
{
  "id": "inventory", "name": "库存核对",
  "keys": ["sku", "warehouse"],
  "sourceConnection": "erp", "targetConnection": "mart",
  "expectedSql": "SELECT sku, warehouse, SUM(quantity) AS quantity FROM stock GROUP BY sku, warehouse",
  "actualSql": "SELECT sku, warehouse, SUM(quantity) AS quantity FROM inventory GROUP BY sku, warehouse",
  "metrics": [{"field":"quantity","tolerance":"0"}]
}
```

可选 `expectedKeyMap` 定义 `connection`、`sql`、`field`、`sourceField`、`targetField`，不限定网点映射。重复映射、缺少分组字段和重复分组均拒绝通过；合并时 NULL 不转换为零。报告用 `group` 对象携带任意分组，桌面与网页都按分组显示。旧规则未提供 `keys` 时继续使用原有日期、网点、渠道口径。

服务配置 `timezone` 控制业务日期，旧配置保留原时区。`envFile` 可省略以使用服务进程的环境变量。此仓库内置核对执行器目前仍使用 MySQL 只读连接；新增执行器应适配 `query/close` 边界，不能声称已支持其他数据库。此次本地修改不会自动部署已运行的服务。

### 数据库与 AI

`lib/databaseDialect.ts` 集中标识符、命名空间、分页和已实现的能力。品牌别名复用数据库引擎。新增引擎需同时实现 Rust 驱动操作、补充此契约并验证真实引擎；单加 logo 或前端枚举不代表支持完成。

`ai/aiTypes.ts` 是模型配置契约；`ai/providers` 负责供应商请求扩展和兼容策略。分析节点只负责角色、任务、schema、重试、取消，不放 DeepSeek 专用请求字段。新增供应商扩展在适配层完成，不散落到每个节点。

已有模型选择保持。新安装不再假定个人电脑上有特定 LM Studio / Qwen 模型；未配置或启动模型明确报未就绪，不输出占位 SQL。

## 存储和兼容

- `lib/jsonStorage.ts` 为脚本、工作区、目录顺序、隐藏项目、显示偏好，以及指标、ETL 定义提供一致的读取、保存和失败通知；损坏原文保留并禁止自动覆盖。其余历史功能配置仍待迁移。JSON 与纯文本偏好分别读写，保持已有存储协议；新增迁移必须保留旧数据读取路径。
- Rust `persistence.rs` 统一连接与看板文件的原子写入：先序列化，再写唯一临时文件、同步并替换。连接 JSON 损坏应报告错误，不再等同“没有连接”。
- 工作区仍用已有版本格式，保留脚本、表、库、看板等身份；不把密码、结果集或未保存编辑加入退出快照。
- 结构化外部数据在进入领域模型时验证；禁止用 `as` 断言代替边界验证。

## 稳定性边界（0.51.1）

### 页面生命周期

`PanelErrorBoundary` 只负责 React 渲染和生命周期错误；不拦截异步请求或事件处理器的异常。网络、数据库执行、文件保存仍必须在各自操作边界处理错误，不能用页面保护替代事务和取消机制。

- `QueryPanel` 按 tab ID 为每个已访问页面保留独立实例和错误边界。切换时隐藏，不重置健康页面；只在用户点击恢复时重新挂载故障页面。
- `features/FeatureHosts.tsx` 是可选界面的组合入口。资产模块故障时保留导航外壳，关闭或切换后隐藏错误页；健康模块继续保留原实例。AI、实体详情分别隔离。
- 重新打开页面不重放用户提交的 SQL、存储过程或分析任务。AI 面板故障卸载时取消废弃流，恢复前消费遗留的自动提问种子。页面读取型初始化可能重新执行。
- 故障页面自身的组件局部编辑可能在 React 卸载时丢失，恢复提示明确说明；不承诺从崩溃组件恢复所有临时编辑。其他正常页面的状态不受重挂载影响。
- 模块导入前的语法/初始化错误、底层 WebView 故障不属于 React 错误边界覆盖范围；本轮未增加进程级自动重启。

### 保存与恢复

`workspacePersistence.ts` 统一脚本和工作区读写。脚本身份重复、字段类型错误、工作区未知版本或未知页面类型均保留原文并阻止覆盖；旧脚本缺少更新时间时按兼容格式读取。脚本读取失败时，也暂停写入依赖这些脚本的工作区引用，防止以空回退值覆盖有效导航。

保存、重命名、删除脚本和目录排序先完成持久化，再提交界面状态。失败不显示成功，不清掉未保存标记。`StorageNotice` 订阅稳定快照，持续显示各项失败；对应操作成功后清除提示，不自动重放之前失败的修改。恢复损坏记录需要先恢复有效配置再重新打开软件，本轮不提供自动清空用户配置的入口。

正常退出先保存工作区；失败后可重试，或明确选择保留上次记录并退出。浏览器预览也会在未保存编辑、执行中的任务或工作区保存失败时触发退出提醒。桌面退出确认仍由现有 Tauri 退出保护负责。

### 本轮验证

`test:resilience` 使用隔离的内存存储验证损坏/新版本配置、拒绝访问、关联脚本保护、配额不足、保存/重命名/删除/排序失败不改变状态，以及修复后的通知清除。它不访问真实数据库和用户配置。

UI 故障注入验证使用真实工作区容器、资产入口、退出保护与提示组件，并用模拟子页面触发异常；检查健康脚本编辑保留、故障模块切换与单独恢复、保存重试，以及深浅主题下的提示布局。该验证不等同于每个数据库驱动的实机测试。


## 查询工作区边界（0.51.2）

- `QueryPanel` 负责页面路由、访问过的页面保活和异常隔离；`WorkspaceTabBar` 负责标签导航；`SqlWorkspace` 负责 SQL 编辑；`QueryResults` 负责结果展示。非 SQL 页面不再创建 SQL 专用筛选、编辑器和拖动状态。
- `lib/queryExecution.ts` 只编排顺序执行，通过端口注入驱动、运行归属、连接有效性和进度回调，不依赖界面、全局 store 或 Tauri。`querySlice` 捕获执行时的连接和数据库，校验每次运行归属；关闭页面、连接被替换或运行被替换后，不再派发旧脚本的后续语句，迟到响应不会覆盖新运行。
- 该保护不会中断已经提交给数据库的当前语句。真正取消当前 SQL 仍需要各驱动提供可定位到该任务的取消接口；不能以关闭页面或停止派发后续语句冒充数据库已取消、回滚。
- 结果选择与执行进度独立：默认跟随执行，用户手动选择结果后不再被后续完成事件抢走。重新执行会重新开启默认跟随。
- `lib/queryResultView.ts` 是无平台依赖的展示模型。按实际执行 SQL、语句序号和附加结果序号分别保存视图设置；同一查询刷新保留有效条件，字段变化时只清除失效字段。该状态限当前标签生命周期，不增加重启时保存结果集的行为。
- 数值字符串比较保持 BIGINT / DECIMAL 精度，NULL 在升降序中均排最后；不会把字符串标识 `001` 与 `1` 的相等判断强行合并。数据库已转换成有精度损失的 JavaScript Number 无法在展示层恢复。
- 表格保存绑定提交时的结果及语句，阻止重复保存和保存期间启动新查询；未保存编辑不能通过切换表格/图表或结果页被无声丢弃。只有实际执行的主结果属于原表预览时才启用编辑，兼容执行器去除末尾分号的行为。
- 结果区调整大小显式指定 tab ID；复制结果使用桌面剪贴板适配层，只有实际写入成功才提示复制成功。

`test:query` 覆盖精确比较、视图身份、刷新校验、执行上下文、迟到回写、手动结果选择、保存竞争、预览分号兼容、明确的拖动归属和剪贴板失败。架构检查同时约束两个新纯模块的传递依赖。模拟 UI 验证覆盖多结果切换、跨脚本切换、重新执行后的筛选排序保持和复制失败反馈，不执行真实 SQL。


## 配置仓储与接入边界（0.51.3）

- `storedRepository` 定义读取/保存契约及可替换的 JSON 存储端口；默认复用 `jsonStorage` 的故障通知与原文保护。调度连接、扫描血缘、文件目录配置分别由功能仓储验证，保留原有 key 和数组格式，不迁移或删除用户数据。格式错误、重复连接/目录 ID 阻止覆盖；配额不足时不提交界面状态、不关闭表单、不显示删除成功。
- 仓储边界不会改变凭据的存储介质或加密方式；本次没有把密码迁入钥匙串，没有添加失效时间。运行会话仍由调度 store 单独持有。截至 0.51.3，血缘运行标注 `opsStore`、AI 偏好等旧配置还未迁移，不能据此宣称全部配置已统一。
- `graphModel` 只接收扫描边、ETL 来源及指标快照，独立生成节点、边和邻接关系。`lineageStore.buildGraph` 暂保留为现有调用点的兼容装配入口。构图测试不用启动应用或数据库；架构检查禁止模型反向依赖 store、平台 API。
- `definitionImport` 显式接收 SQL 解析器、文件清单和路径映射，不读取 ETL store 或本地配置。解析器不可用时保留任务、依赖和失败说明；存在旧数据流时保留并标明尚未重新验证，其他任务继续处理。规范化结果支持只提供 sources/target 的解析器，不要求外部必须返回 flows。
- `fileScope` 负责目录与调度器的关联范围。未关联目录只更新自身；关联目录仅使用同一调度地址和已关联目录的映射。不同调度器不会共享映射。映射配置读取失败时阻止依赖它的任务同步，不以空回退配置重新生成血缘。路径匹配优先更具体的前缀；冲突映射及重复确切路径视为未解析，不按数组先后猜测。
- 文件扫描先保存目录配置，再通过一次 ETL 清单写入发布文件与相关任务；ETL 写入失败时保留原任务状态。两种配置并非跨 key 事务：目录配置可能已保存，但失败的扫描清单不会发布，界面明确报告失败，可再次扫描。
- ETL/指标血缘解析部分失败时保留旧扫描证据并注明失败；不能把解析器故障解释为来源关系消失。完整成功扫描才替换对应来源的旧边。保留的旧证据可能已过时，后续成功重扫会更新，不宣称它已经重新验证。

`test:boundaries` 覆盖旧配置兼容、损坏记录保护、保存失败不改变状态、扫描失败恢复 busy、独立构图、解析器替换、跨调度目录隔离、未关联目录、路径歧义和单次 ETL 发布。所有数据均为隔离测试夹具，不连接用户数据库、调度器或付费模型。修正了测试缓存清理在 macOS 临时目录符号链接下的路径问题，确保每组夹具重新初始化模块。


## 运行巡检边界（0.51.4）

- `opsTypes` 保存领域类型；`opsModel` 根据显式输入计算运行状态合并、ETL 调度推断和巡检发现，时钟由调用者传入，不读取全局 store、存储或外部 API。`opsStore` 只负责捕获输入、调用规则、保存后发布结果。
- `opsRepository` 接管 `dbstudio.lineageOps.v1`。兼容旧记录缺少 ops/health 映射，但校验每项状态、时间、标注和可选阈值。损坏记录保留原文并阻止覆盖；保存失败保留当前标注和状态，报告错误。AI 等其他旧配置仍待迁移。
- `schedulerOpsAdapter` 把连接、项目、工作流、实例、任务和 ETL 关联转换成普通节点快照。来源范围使用调度类型、地址、项目的稳定组合。合并只替换该来源拥有的记录及本次明确关联的节点，保留其他项目和手工标注。旧记录没有来源身份时只认领本次能明确关联的节点，不按猜测删除全部历史记录。
- 运行健康独立记录来源；修改负责人后，下一次工作流运行尚无任务记录时，不沿用上一次任务的成功状态。多个生产任务对应同一表时不选一个任务冒充整表健康。当前血缘表节点仍以 database.table 标识，尚未完成所有连接的表节点身份迁移，跨实例同名对象要保守看待。
- 调度项目加载中、断开或报错时不更新运行快照；有效的空项目可以清掉本来源已有记录。0.51.4 时此契约仍依赖调度 store 提供正确的当前项目观察；0.51.5 的请求归属管理见后文。
- 原始状态由 Provider 的 `classifyRunState` 解释。DolphinScheduler 的 `SUBMITTED_SUCCESS` 为运行中，只有确切成功状态才记为成功；未实现解释器的调度器返回 unknown。公共巡检模型不依赖任何外部调度产品的状态命名。
- 不再默认将两天未运行视为陈旧。节点可选配置“运行记录最长间隔（小时）”，留空不按间隔告警。它检查运行记录，不证明目标表数据的新鲜度，也不解析自由文本 SLA 或自动推断 cron 周期。
- 目录推断遇到多个不同调度表达式时说明歧义，不按数组顺序选一个；损坏的 ETL 清单不能作为删除全部运行标注的依据。
- 扫描血缘与运行标注仍是两个独立持久化记录。移除节点时若前者保存成功、后者失败，界面如实显示部分完成并允许重试，不宣称跨记录原子事务。

## 调度请求与命令边界（0.51.5）

- `schedulerStore` 仅装配配置仓储、Provider、ETL 接口、解析器、ID 和时钟。`createSchedulerStore` 在独立实例内管理状态与计时器，测试可直接注入假适配器，无需加载 Tauri 或真实配置。`schedulerState` 集中定义状态契约。
- `requestScope` 负责作用域失效、最新请求归属和进行中标记。连接重连/切换、活动连接配置修改/删除使旧连接请求失效；项目选择生成新的访问作用域，因此 A→B→A 也不会接收第一次 A 的迟到结果。成功、失败和收尾状态均检查归属。
- 项目数据、统计、任务详情、日志、任务定义分别管理请求归属。关闭日志不会被旧响应重新打开；收起任务详情后不会接收迟到任务列表。统计不阻塞主数据刷新，旧统计请求也不能覆盖新一轮读取。
- 自动与手动刷新共用数据读取通道；处理中收到的刷新合并为一次后续读取，不并行堆积。切换项目清掉旧队列，关闭面板/停用自动刷新停止计时器和排队刷新；已经发出的只读请求可在同一上下文完成，不冒充底层网络请求已取消。
- `definitionSync` 是显式输入输出的取定义→解析→发布服务。每个异步边界检查归属，失效时不再派发后续工作流或发布 ETL 清单。背景项目同步可在同一连接内继续，但不覆盖其他项目的页面消息。保留既有 DolphinScheduler ID；新适配器使用自己的命名空间。
- `schedulerActions` 统一命令发送与锁管理。连接和项目在发送前捕获；同一连接/项目只允许一个未完成命令。导航不会释放远端已发出的命令锁，返回原项目仍能看到进行中状态。旧命令结束不能清掉其他项目新命令的 busy 状态，也不触发新页面的刷新或错误提示。
- 命令锁属于客户端重复提交保护，不能替代服务端幂等键。已经发送的运行、停止、上下线等请求仍可能在远端执行；本次未增加远端取消/撤销功能，也没有在实际调度器上执行验证。切走后的命令结果暂不保存为独立操作历史。
- 编辑连接后清理旧会话，需要重新连接；保存配置失败则保留旧连接、表单和请求上下文。不同运行实例的计时器独立，`dispose` 可供测试或宿主释放。

`test:scheduler` 用可控延迟与乱序的 Promise 验证重连与 A→B→A、迟到项目列表/错误/统计、刷新合并、任务/日志开关、原始命令上下文、重复提交锁、删除连接失败与恢复、独立计时器和失效定义不发布。与其余十组回归及类型检查一并作为构建前置门槛。

## 分析草稿与工作流编排边界（0.51.7）

## 任务查询会话与模型故障恢复（0.51.10）

- `queryRuntime` 持有实例内缓存和进行中请求，`datasetSql` 提供纯只读校验；生产 `query` 仅装配指标目录、方言和只读传输。刷新推进缓存代次，后续查询不会复用刷新前的请求，旧请求结束也不能覆盖新缓存或移除新请求。缓存入库和返回均复制结果，避免调用方修改影响其他消费者。
- `queryGate` 独立管理传输并发，界面查询、分析会话、分析维度探测共用三槽预算。排队取消会移除该请求；释放槽位时直接移交给下一等待者，避免新请求抢占导致超过上限。会话释放停止排队并拒绝晚返回结果，但不声称已经终止数据库服务端正在执行的语句。
- `toolRegistry` 与 `dataToolRuntime` 提供可注入工厂，每个分析任务拥有自己的工具、查询计划与结果。计划捕获目录，重复执行有版本保护，校验总计不能附到另一次执行结果上。旧门面保留给兼容调用方；生产工作流不再依赖其全局计划，也不在启动时清空界面或其他任务的缓存。
- `analysisSession` 统一捕获整次运行的指标目录和连接方言，装配规划、取数、校验、补充调查、分析、设计、复核和预览。`previewData` 脱离 DOM，通过同一会话的工具生成和验证组件查询；各等待点检查取消，包括总计校验完成时。正常结束、失败和取消均释放查询会话，展示所需证据已经包含在结果中，成功看板预览沿用工作区既有生命周期。
- 看板编辑服务仍从实时目录解析引用，因此生成与保存前核对目录是否变化；发生变化明确要求按新定义重跑，防止旧数据证据绑定新口径。编译、预览及保存工具接受会话接口；已经保存成功仍保留真实回执。截图评审候选仍按 workflow ID 管理，并未在本轮完全替换为独立仓储。
- `httpRetry` 处理明确的临时 HTTP 响应：408、429、500、502、503、504 最多增加两次请求，退避等待支持取消并遵循不超过 30 秒的 Retry-After。预算在一次结构化模型调用的格式修复间共享；不重试密钥/权限/无效参数错误，不自动切换模型。服务错误与 JSON Schema 不支持分开分类，HTTP 500 不再被误用为格式降级依据。无法恢复时返回简明状态及重试次数；未收到的服务计费信息不能推算。

`test:query-runtime` 覆盖刷新代次、在途合并、返回值隔离、TTL、跨会话计划、总计/执行生命周期、共享并发、排队取消和独立预览接口；`test:model-recovery` 用模拟服务复现截图 HTTP 500，验证真实结构化请求自动恢复、耗尽上限、原模型/原请求保持、权限错误、格式兼容和取消。真实生产装配回归增加运行中编辑目录及全局计划不可见断言。全部十八组测试与类型检查纳入构建门槛，未访问生产数据库或付费模型。

后续仍包括截图评审和看板草稿仓储的彻底实例化、界面结果表格职责、Rust 命令门面及其余跨功能依赖。这次完成的是查询会话边界和临时模型服务故障恢复，不能保证外部模型服务永远可用，也不代表全部解耦工作结束。


## 启动自动连接（0.51.11）

加载连接配置后，在后台使用现有 `connect(id, null)` 通道连接非 SQLite 实例。后端先读取本机加密凭据，没有凭据就返回 `CREDENTIAL_REQUIRED`，不会尝试空密码认证；SQLite 没有登录凭据，不属于本次自动连接范围。密码保存位置和长期有效策略保持不变，不新增前端凭据读取接口。

每次应用存储实例只启动一轮，最多三个连接同时进行，已连接、正在连接或已删除的实例跳过。React 重复初始化和连接列表刷新不会重复触发，也不会把用户主动断开的连接再次接上。没有密码静默跳过，失败连接汇总提示，正常界面继续使用；自动连接不打开或关闭手动密码窗口，不刷屏成功提示。手动连接仍可输入更新后的密码。`test:startup` 覆盖后台启动、并发限制、重复初始化、失败隔离、缺少/变更密码和手动登录行为，全部十九组检查纳入构建；测试不访问真实数据库。
